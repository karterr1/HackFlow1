# HackFlow — работающий MVP

Платформа студенческого хакатона: Flask REST API + React/Vite + Tailwind CSS, PostgreSQL, SQLAlchemy, Flask-Migrate, Flask-Login, CSRF, Lucide. Интерфейс на русском.

Это реализация основного пользовательского пути из этапа 1 ТЗ с несколькими дополнительными функциями, а не полная реализация всех 39 разделов. Состояние функций перечислено ниже.

## Быстрый запуск: Windows / macOS / Linux

Установите Docker Desktop с Docker Compose. На Windows включите WSL2. Распакуйте архив и откройте терминал в папке `hackflow`.

1. Скопируйте `.env.example` в `.env`:
   - Windows PowerShell: `Copy-Item .env.example .env`
   - macOS/Linux: `cp .env.example .env`
2. Измените `SECRET_KEY` на случайную строку, например сгенерированную `python -c "import secrets; print(secrets.token_hex(32))"`.
3. Измените `POSTGRES_PASSWORD` и пароль в `DATABASE_URL` на одинаковое значение. Для удобства используйте случайные латинские буквы и цифры; специальные символы в URL нужно кодировать.
4. Выполните:

```sh
docker compose up -d --build
docker compose exec web flask --app app:create_app db upgrade
docker compose exec web flask --app app:create_app seed
```

Откройте **http://localhost:8080**.

Команда `seed` создаёт только демоданные, если пользователей ещё нет. Если нужен демонстрационный набор, выполните её до создания администратора.

```sh
docker compose exec web flask --app app:create_app init-admin
```

Администратор создаётся интерактивно, пароль не передаётся в командной строке. Для обычной остановки: `docker compose down`. Данные остаются в томе `postgres_data`. Не удаляйте том, если нужны данные.

Все пароли: `HackFlow2026!`. Только для локальной демонстрации.

| Email | Доступ |

## Проверка основного сценария

1. Войдите участником `member`. Откройте «Команда», введите код HACKFLOW-DEMO.
2. Откройте «Кейсы» и изучите задачу. Капитан может выбирать кейс.
3. В «Обучении» откройте реальный внешний материал, отметьте его изученным.
4. В «Расписании» откройте ссылку события. В демоданных находится ссылка на учебные материалы, а не выдуманный действующий вебинар. Организатор может добавить настоящую ссылку Zoom/Телемост.
5. В «Доске задач» создайте задачу. Переместите её мышью или измените статус выпадающим списком. Назначьте участника. Через «Редактировать» задайте описание и срок.
6. Отправьте сообщение в «Чате команды». Откройте второй аккаунт в другом браузере: сообщения обновляются раз в 5 секунд.
7. Войдите капитаном, откройте «Сдача проекта». Укажите название, описание и настоящие URL презентации, репозитория, демонстрации. Отправьте проект. Сохраняются время и итоговая версия; повторная сдача запрещена.
8. Войдите организатором. В «Управлении» откройте проект команды и её задачи.
9. Попробуйте добавить участника вручную или импортировать `examples/admissions.csv`. Новая регистрация сама по себе допуска не даёт.
10. Добавьте учебный материал, событие или объявление. У участников появятся уведомления.
11. В «Настройках» переключите все три темы. Выбор сохраняется в браузере.

## Что реализовано

- Регистрация, вход, выход, хеширование паролей, защищённые сессии и CSRF.
- Проверка допуска к закрытому хакатону, CSV/ручной импорт.
- Создание мероприятий организатором и отдельный владелец каждого хакатона.
- Команды, капитан, приглашение по коду, ограничение вместимости.
- Уникальное ограничение `(user_id, hack_id)` в базе: нельзя состоять в двух командах одного хакатона.
- Удаление команды капитаном/организатором до старта через API; кнопка у капитана до старта.
- Публикация и выбор кейса капитаном.
- Kanban с четырьмя статусами, drag-and-drop, описаниями, ответственными и сроками.
- Командный чат с историей, автором и временем; защита от чтения чужой переписки.
- Учебные материалы, индивидуальные отметки изучения, расписание, внешние ссылки, объявления.
- Создание, изменение и удаление расписания/материалов организатором.
- Итоговая сдача капитаном до дедлайна, сохранение в БД, доступ организатора, журнал отправок.
- Внутренние уведомления об изменениях материалов, чате и отправке проекта.
- Панель организатора с реальными количествами участников, задач и решений.
- Создание администратора через CLI, назначение/снятие роли организатора и блокировка пользователей.
- Три темы, адаптивная навигация, дорожная карта на основе совершённых действий.
- Миграции, Docker, воспроизводимая сборка frontend, API-тесты.

## Что ещё не реализовано

Это честные границы текущего MVP:

- Восстановление пароля по email, загрузка аватаров и редактирование профиля.
- Заявки в открытые команды, передача капитанства, предварительное формирование команд организатором.
- Загрузка файлов: презентация и дополнительные материалы пока передаются внешними ссылками. CSV — единственная загрузка, ограниченная 2 МБ.
- Автоматическая проверка доступности GitHub/демо и наличия README, GitHub REST-интеграция.
- Персональные назначения экспертов и комментарии, приватный чат капитана с организатором.
- Приглашения жюри, назначения работ, обезличивание, оценивание, публикация результатов.
- Рейтинги, календарь активности за год, апелляции, Peer Review.
- CodeCheck, анализ ИИ-кода, Smart Control и расширенная аналитика.
- Рассылка email/Telegram, автоматические уведомления по таймерам дедлайнов.
- Публичное размещение, GitHub-репозиторий и презентация для конкурса не создавались.

Глобальная роль `jury` существует только как заготовка. Она не даёт доступ к закрытым данным. Кабинета жюри пока нет.

## Разработка без Docker

Нужны Python 3.11+ и Node.js 22+. Из корневой папки:

```sh
python -m venv .venv
```

Активация Windows: `.venv\Scripts\Activate.ps1`.
Активация macOS/Linux: `source .venv/bin/activate`.

```sh
pip install -r backend/requirements.txt
cd backend
flask --app app:create_app db upgrade
flask --app app:create_app seed
flask --app app:create_app run --port 5000
```

Без `DATABASE_URL` используется локальная SQLite в `backend/instance/` — только для быстрой разработки. Для PostgreSQL задайте переменные окружения `DATABASE_URL` и `SECRET_KEY` до запуска. При запуске без Compose файл `.env` автоматически не загружается.

Во втором терминале:

```sh
cd frontend
npm ci
npm run dev
```

Откройте `http://localhost:5173`. Vite проксирует `/api` на Flask, оба интерфейса используют cookie-сессии.

Для production-сборки: `npm run build` из `frontend`. После этого Flask сам раздаёт `frontend/dist`.

## Тесты

Из корневой папки после установки backend-зависимостей:

```sh
python -m pytest -q backend/test_app.py
```

Тесты запускаются в изолированной SQLite в памяти и не затрагивают рабочую базу. Проверяются полный основной путь, IDOR/защита команд, допуск, дубли команд, роль капитана, CSRF, дедлайн, импорт CSV и публикация ресурсов. Этот же набор дополнительно проверен на PostgreSQL 16; подробности в VERIFICATION.md. Браузерное тестирование не выполнено.

## Публичное развёртывание

На сервере с Docker:

1. Загрузите этот проект; создайте `.env` с отдельными сильными секретами.
2. Запустите Compose, миграции и `init-admin`. Для реального мероприятия не создавайте демоаккаунты; для демонстрации примените seed перед init-admin.
3. Настройте HTTPS reverse proxy (Caddy/Nginx) на порт 8080, домен направьте на сервер.
4. Установите `COOKIE_SECURE=1`, `FRONTEND_ORIGIN=https://ваш-домен` и перезапустите web.
5. Ограничьте прямой доступ к порту 8080 через межсетевой экран. PostgreSQL наружу в Compose не публикуется.
6. Настройте резервные копии PostgreSQL и проверьте восстановление. Перед публичным запуском смените/заблокируйте демоаккаунты.

Секреты не коммитить. Ограничитель входа использует память процесса; для нескольких workers нужен общий Redis через `RATELIMIT_STORAGE_URI=redis://...` и Python-пакет `redis`. Облачный SMTP, резервирование, мониторинг и распределённый limiter в этом архиве не настроены. При постоянном `SECRET_KEY` сессии сохраняются между перезапусками.

Для безопасности сервер не загружает произвольные внешние URL: ссылки проверяются по схеме http/https, отображаются как ссылки и не используются для SSRF-запросов. React экранирует пользовательский текст; HTML из материалов не исполняется. Пароли хешируются Werkzeug. Идентификаторы команд и роли проверяются в Flask, не только в интерфейсе.
